# AI-журнал

## Лабораторная №1. Анализ требований

**Задача:** черновик требований для системы учёта заявок.
**Модель:** ChatGPT, GPT-4.
**Промпт:** "Ты системный аналитик. Составь требования для учебной системы учёта заявок. Контекст: заочка, специальность 09.02.07, стек Python + SQLite. Формат: 4 роли с правами; 10 функций в формате Система должна...; 5 нефункциональных; 5 сущностей с полями; 5 критериев приёмки. Без воды. Не предлагай email-уведомления и интеграции."
**Почему такой промпт:** задал роль, контекст, формат и запреты, иначе ИИ тянет в энтерпрайз.
**Почему GPT-4:** хорошо держит структуру.
**Результат ИИ:** 4 роли, 12 функций, 5 нефункциональных, 6 сущностей, плюс роль Гость и email-уведомления.
**Проверка:** сверил с методичкой, всё есть. Противоречий нет.
**Что исправил:** убрал роль Гость, убрал email-уведомления, добавил требование про историю изменений.
**Вывод:** ИИ экономит время, но без чёткого промпта результата нет.

## Лабораторная №2. Git

**Задача:** команды Git для учебного проекта и .gitignore.
**Модель:** Claude 3.5 Sonnet.
**Промпт:** "Я студент, делаю проект на Python. Нужен Git-workflow: репозиторий, ветка develop, 5 коммитов, merge в main, push на GitHub. Дай команды с пояснением. Шаблон .gitignore для Python + SQLite. Не пиши опасные команды без предупреждения."
**Почему такой промпт:** указал, что студент, попросил предупреждать про опасное.
**Почему Claude:** хорошо объясняет пошагово.
**Результат ИИ:** workflow, шаблон .gitignore, объяснение reset --hard и push --force.
**Проверка:** выполнил команды, проверил git log.
**Что исправил:** заменил "update files" на осмысленные сообщения коммитов, не использовал push --force.
**Вывод:** команды надо понимать, а не копировать.

## Лабораторная №3. Архитектура

**Задача:** 2 архитектурных варианта и ревью диаграммы.
**Модель:** GPT-4.
**Промпт:** "Требования: система учёта заявок, 4 роли, статусы, комментарии, история, учебный проект Python + SQLite, разработчик один. Предложи 2 архитектурных варианта, сравни по простоте, тестируемости, расширяемости. Формат таблица. Не предлагай микросервисы и DDD."
**Почему такой промпт:** ограничил масштаб, чтобы ИИ не лез в тяжёлое.
**Результат ИИ:** слоистая и MVC, сравнительная таблица.
**Проверка:** выбрал слоистую сам. Ревью нашло 3 замечания.
**Что исправил:** принял перенос проверки прав в сервис, принял уборку HTTP из сервиса, отклонил возврат объекта вместо dict.
**Вывод:** ИИ как второй взгляд полезен, но не всё надо принимать.

## Лабораторная №4. Интерфейс

**Задача:** UX-чек-лист и критика прототипа.
**Модель:** GPT-4.
**Промпт:** "Составь UX-чек-лист для системы учёта заявок. Пункты: навигация, формы, ошибки, пустые состояния, фильтрация, доступность, статусы. Формат: пункт + пояснение."
**Почему такой промпт:** задал конкретные темы.
**Результат ИИ:** чек-лист 20+ пунктов, потом критика макетов (6 замечаний).
**Проверка:** сверил замечания с макетами.
**Что исправил:** принял 4 замечания, отклонил 1, частично 1.
**Вывод:** ИИ находит то, что сам не замечаешь.

## Лабораторная №5. База данных

**Задача:** ER-модель, schema.sql, seed.sql, запросы.
**Модель:** GPT-4.
**Промпт:** "Сущности: Users, Roles, Requests, Statuses, Categories, Comments, RequestHistory. Связи: заявка у автора, может иметь исполнителя, статус, категория; комментарии и история привязаны к заявке. СУБД SQLite. Предложи ER-модель и schema.sql с PRIMARY KEY, FOREIGN KEY, NOT NULL, UNIQUE. Отдельно seed.sql и 5 SELECT с JOIN."
**Почему такой промпт:** описал сущности сам, разделил задачи.
**Результат ИИ:** схема, но без FK на Users в Comments, пароли открыто, ON DELETE CASCADE.
**Проверка:** выполнил схему в SQLite, проверил через PRAGMA.
**Что исправил:** добавил UserId в Comments, заменил пароли на хеши, заменил CASCADE на RESTRICT, LEFT JOIN на INNER JOIN.
**Вывод:** ИИ даёт заготовку, каждая деталь проверяется.
